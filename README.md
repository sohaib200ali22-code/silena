# Silena

Silena is a private, single-server Discord moderation bot. Every slash command is restricted at runtime to the configured `OWNER_ID`, must be used in `GUILD_ID`, and also checks the owner's required server permission and Silena's required bot permission. Commands are registered as guild commands for that one server. If Silena is already in, or is later added to, another server, it attempts to leave that server and logs the event.

## Configuration

Copy `.env.example` to `.env` for local use and fill in all seven required values:

| Variable | Description |
| --- | --- |
| `DISCORD_TOKEN` | Bot token from the Discord Developer Portal. Keep it secret. |
| `CLIENT_ID` | Application ID from the Developer Portal. |
| `GUILD_ID` | The one Discord server where Silena is allowed to operate. |
| `OWNER_ID` | The Discord user ID allowed to run Silena's moderation/admin commands. |
| `STAFF_ROLE_ID` | The configured server role allowed to view and close support tickets. |
| `TICKETS_CHANNEL_ID` | Text channel where closed-ticket transcript files are archived. |
| `LOGS_CHANNEL_ID` | Private text channel where deleted/edited message copies and audit details are sent. |

Enable the **Message Content Intent** for the bot in the Developer Portal so automod and message audit copies can inspect message text. Silena also requests the privileged **Server Members Intent** for `/silena`'s new-member account-age checks; enable it in the Developer Portal or Discord login will fail with `Used disallowed intents`. Direct message support uses the `DirectMessages` gateway intent and a partial DM channel; no additional privileged intent is required. Invite it to the configured server with the `bot` and `applications.commands` OAuth scopes and only the permissions it needs: View Channels, Read Message History, View Audit Log, Send Messages, Embed Links, Attach Files, Manage Messages, Manage Channels, Manage Roles, Moderate Members, Kick Members, and Ban Members. The `LOGS_CHANNEL_ID` channel must be private to staff and Silena, with View Channel, Send Messages, Embed Links, and Attach Files granted to Silena; server-level View Audit Log is needed to resolve deletion actors. The command runner also checks the caller's corresponding Manage Messages, Manage Channels, Moderate Members, Kick Members, or Ban Members permission.

Create a staff role and a private text channel for archived ticket files in the configured server. Set their IDs as `STAFF_ROLE_ID` and `TICKETS_CHANNEL_ID` locally or in Render's environment settings. The staff role should be mentionable, or the bot must have Mention Everyone permission, for ticket creation to ping staff. Users can open tickets only by pressing **Create Ticket** on a published Silena ticket panel; a form collects the subject. There is no `/ticket` command. Silena restricts each ticket channel to the opener, this role, and the bot, and posts a **Close ticket** control panel inside it. Only members with the configured staff role can use that button and provide a reason; there is no `/close` command or alternate user-facing close path. If the opener has not replied within 30 minutes of the latest staff message, Silena sends them a private reminder; it does not automatically close the ticket. A visible marker in the ticket prevents duplicate reminders after restart. Closing posts the reason in the ticket, uploads a text transcript to `TICKETS_CHANNEL_ID`, then deletes the ticket channel only after Discord confirms the archive upload. The transcript includes authors, timestamps, message content, attachment/embed URLs, and the close reason; it is oldest-first and capped at 7 MiB / 10,000 scanned messages, with truncation noted in the file. If transcript creation or upload fails, the ticket channel is not deleted. If staff notification or the close control panel cannot be posted after ticket creation, Silena tries to delete the unconfigured channel; if cleanup also fails, it reports the orphan channel.

`/ticket-panel` (owner only) opens a private form prefilled with the default panel title and message, then shows a branded ephemeral preview with **Send**, **Edit**, and **Cancel** actions; nothing is posted before **Send** is selected. The editable title and message are limited to 256 and 4,000 characters. The published panel retains its **Create Ticket** button and disables automatic mention parsing. `/announcement` (owner only) has the same private form and preview flow, and posts in the current channel or an optional text-channel destination. Mentions in the title/message do not notify users. By default, automatic mention parsing is disabled. The optional `mention_everyone:true` setting requires the owner and bot to have Mention Everyone permission, visibly warns in the preview, and requires a second **Confirm @everyone** action before sending the literal mention; only that everyone mention is allowed, never user or role mentions.

Configuration is validated on startup and command deployment. Discord IDs must be 17-20 digit IDs. Never commit `.env` or put a real token in source control.

## Moderation and automod

Commands: `/clear`, `/lock`, `/unlock`, `/slowmode`, `/serverinfo`, `/userinfo`, `/silena`, `/ticket-panel`, `/announcement`, `/timeout`, `/untimeout`, `/warn`, `/kick`, and `/ban`. Tickets are opened and closed through their respective posted panel buttons. `/slowmode` sets a 0-21,600 second delay in the current text channel (0 disables it); `/serverinfo` displays server and channel counts; `/userinfo` shows a selected member's account age, join date, and roles. `/silena status` reports Guard state; `/silena enable` starts an ephemeral, owner-only sequence requiring three distinct button confirmations within 15 minutes; `/silena disable` turns protections off immediately. Guard starts **OFF** and remains off until all confirmations are completed. When on, it enables the configured invite/link, mass-mention, and anti-spam protections and kicks non-bot accounts created less than 7 days ago on join. A burst above `SPAM_MAX_MESSAGES` within `SPAM_WINDOW_SECONDS` removes all messages recorded in that burst and applies a one-hour timeout when Silena has Moderate Members permission and can moderate the member. The action is logged and Silena attempts to DM the user; if timeout permission/hierarchy prevents timeout, it still attempts to delete the burst and logs the failure. The configured bot owner, server owner, administrators, and bot accounts are exempt. The join kick uses Discord's audit log reason and attempts to DM the user first; hierarchy/permission failures are logged. Guard state is intentionally in memory and resets to OFF after every process restart/redeploy, so a restart never silently re-enables enforcement. `/silena` is owner-only and requires Manage Server; enabling additionally requires Silena's Kick Members permission. The other information/moderation commands are owner-only and also require their corresponding Discord permissions. Successfully applied `/warn`, `/timeout`, `/untimeout`, `/kick`, and `/ban` actions trigger a private notice to the target with the reason (and timeout duration where relevant). If the target blocks DMs, the moderation action still stands; Silena logs the delivery failure and reports the DM status to the moderator. `/clear` without a user still deletes the requested 1-100 recent messages. With a user selected, it scans at most the latest 1,000 messages in the current channel, previews the match count, and requires confirmation before deleting matches. An optional amount caps how many matching messages are deleted (up to 1,000); messages older than 14 days are deleted individually, while newer matches are bulk deleted. The result reports scanned, matched, deleted, skipped (non-matches or matches beyond the cap), and failed counts. Lock and unlock apply only to the current text channel (not threads or voice channels) and change only the `@everyone` `SendMessages` override. Unlock removes that override so the channel inherits its category/server policy; it does not force the channel open if the category remains locked. Moderation actions include a reason where supported and are written to the process logs; Discord's own audit log receives reasons for individual deletions, timeouts, kicks, bans, and channel permission changes. `/warn` is a logged, visible warning only; warnings are not stored as a case history.

Message deletions and edits in the configured server are copied to `LOGS_CHANNEL_ID` with the author ID, channel/message IDs, timestamp, and before/after content; available attachment and embed URLs are included. A single-message deletion actor is shown only when a recent, matching Discord audit-log entry provides a unique executor. Bulk deletion attribution is shown only for a unique matching audit entry with the same channel and deleted-message count; otherwise the log explicitly says unknown. Discord may omit content for uncached deleted messages, and audit entries can be delayed or ambiguous, so attribution/content cannot always be recovered. Silena skips audit copies originating in the log channel to prevent recursion. `/untimeout` removes an active timeout, requires the owner's Moderate Members permission, respects role hierarchy, logs the action, and notifies the target by DM where possible.

When `/ban` is issued, Silena attempts the user's DM before applying the ban because Discord may reject a DM once the user no longer shares a server with the bot. The DM explicitly says they were banned and instructs them to reply directly to that message to appeal; the ban still proceeds if DM delivery fails. The bot forwards a reply to that specific marked ban notice to the private `LOGS_CHANNEL_ID` channel and mentions the configured bot owner for review. The owner can choose **Approve and unban** or **Reject appeal**. Approval removes the ban and sends the user a decision DM; rejection keeps the ban and sends a decision DM. Decisions are audited, and a failed DM does not undo the owner’s decision. The bot suppresses repeat submissions for the same ban notice while it is running; that short-lived duplicate guard resets on restart. Appeal records and review buttons remain in the Discord log channel, so pending decisions remain reviewable after restart. Only the configured owner can use review buttons, and approval also requires Ban Members permission for both owner and bot.

Automod removes configured invite links, `@everyone`/`@here` and messages with more than five user/role mentions. With Guard on, a message burst above the configured threshold triggers deletion of the burst and an attempted one-hour timeout; it never automatically bans users. Server administrators and the configured bot owner are exempt from automod. Defaults and environment controls:

| Variable | Default | Behavior |
| --- | --- | --- |
| `BLOCK_INVITES` | `true` | Remove Discord invite links. |
| `BLOCK_LINKS` | `false` | Also remove ordinary HTTP(S) and `www` links. |
| `SPAM_MAX_MESSAGES` | `5` | Number of messages allowed per user in the rolling interval; the next message triggers burst deletion and an attempted one-hour timeout (3-20). |
| `SPAM_WINDOW_SECONDS` | `8` | Rolling interval used to identify a message burst (3-60 seconds). |

## Local development

```sh
npm install
npm test
npm start
```

On Discord client startup, Silena registers its slash commands to the configured guild and logs the number registered. `npm run deploy:commands` is also available for manual registration and updates only that guild's command set. Keep the bot token private and do not run multiple bot instances with the same configuration unless you intend them to share the same gateway connection.

## Render

The included `render.yaml` defines Silena as a long-running Node background worker. Create or update the service from the Blueprint and set `DISCORD_TOKEN`, `CLIENT_ID`, `GUILD_ID`, `OWNER_ID`, `STAFF_ROLE_ID`, `TICKETS_CHANNEL_ID`, and `LOGS_CHANNEL_ID` in Render's environment settings; the Blueprint deliberately does not contain secret values. Set optional automod variables there if you want different defaults. Render runs `npm ci` to build and `npm start` to launch the bot. Once Discord login succeeds, Silena registers slash commands in `GUILD_ID`; confirm logs show `slash_commands_registered` with the expected command count.

Silena also starts an Express health endpoint at `GET /health` on `0.0.0.0:$PORT` (default port `10000`). It returns HTTP 200 when the Discord client is connected and 503 while it is starting. Render background workers do not expose inbound HTTP traffic or use web-service health checks, so this endpoint is not required for the current worker deployment; it is available if you later run Silena as a Render Web Service. An HTTP listener failure is logged but does not prevent Discord login.

If registration fails, inspect Render logs for `slash_command_registration_failed` and verify that `DISCORD_TOKEN`, `CLIENT_ID`, and `GUILD_ID` all refer to the same Discord application/server setup and that the bot is installed in that guild with the `applications.commands` scope. Do not deploy or paste the token into source files or logs.

## Possible future commands

Useful next improvements: persistent moderation cases with `/warnings` and case lookup; configurable automod exemptions for trusted roles/channels; and a configurable slowmode/escalation response for repeated spam. Message auditing also cannot recover uncached deleted content or identify a moderator when Discord's audit entry is missing or ambiguous.
